# 1.1 观测与正确性

假设一个请求在 0 ms 入队，在 80、100、120 ms 各拿到一个 token。它的首 token 等待（TTFT）是 **80 ms**，相邻 token 的间隔（TBT）是 **20、20 ms**。产生这些 token 的引擎步各有自己的耗时记录，一个步也可以同时为多个请求产出 token。最后还能用 HF 给一组固定输入的输出打分，检查模型有没有退化。

## 要记住的 why

1. **CPU 和 GPU 要分别计时。** CPU 提交前向后就能继续，`.tolist()` 取回结果时才等待 GPU。只给 `run_model()` 加 CPU 秒表会低估前向耗时。计时会多插几个 CUDA event，在 `.tolist()` 前插完、返回后读数，可以沿用已有的等待。
2. **高 `gpu_busy` 还要看时间线。** CUDA event 的间隔包含 kernel 之间的空隙。A10G 上单请求 700-token prefill 的前向跨度约 **44 ms**，kernel 覆盖区间合计约 **14 ms**，报告仍显示 **95.1%**。采集时间线本身会增加一些开销。
3. **按步和按请求都要记录。** 总吞吐会盖住首 token 等待、出 token 的停顿和抢占。逐步记录和每个 token 的时间戳有存储与记账开销。用固定种子和虚拟步注入负载，方便重放到达条件。
4. **用输出评分抓计算错误。** 程序能生成 token，attention 也可能已经算错。用 HF 的输出做公共前缀比较，再用 HF 给 nano 的输出算 NLL。要多跑一份模型，均值和容差也可能掩盖少量样本的退化。

## 代码映射

- `ModelRunner.run()` 填 CPU 计时和 GPU event 计时，`LLMEngine.step()` 补上调度、后处理和总墙钟，每步产出一个 `StepRecord`。
- `Sequence` 记请求进入和每个输出 token 的时刻，`Scheduler` 记抢占与完成。引擎每步收走名单，给刚完成的请求各建一条 `RequestRecord`，用来算 TTFT 和 TBT。
- `bench.run.drive()` 按虚拟步提交请求，报告按 prefill 和 decode 分组汇总，trace 保留每一步的明细。
- `bench.correctness` 用 `greedy_match()` 比较 HF 和 nano 输出开头连续匹配的 token 数，用 `teacher_forced_nll()` 给 nano 输出打分，再由 `compare()` 用八个 prompt 的均值和基线比较。

## 调用链

- 观测走 `drive()` → `LLMEngine.step()` → `Scheduler.schedule()` → `ModelRunner.run()` → `Scheduler.postprocess()` → 两类记录 → 报告或 trace。入口见 `bench/run.py:15`、`nanovllm/engine/llm_engine.py:53`。
- 正确性走 nano 生成 → HF 生成及评分 → `greedy_match()` / `teacher_forced_nll()` → `compare()`。入口见 `bench/correctness.py:95`。
- DeepInfer 用 `CUDATimer.record()` 存下 event 对，再由 `flush_out()` 汇总，非阻塞模式会先查结束 event 是否跑完。它的离线正确性测试要求每个样本的 PPL 与基线严格相等。`reference/DeepInfer/deepinfer/timer.py:233`、`reference/DeepInfer/tests/models/test_offline_inference.py:158`

## 实测验收

Qwen3-0.6B 在原始 L4 实验中只给出了 **1,690.67 tok/s**。A10G 的同类观测实验把耗时拆开，代表性 decode 步的 CPU 提交约 **0.41 ms**、GPU 前向约 **39.94 ms**、CPU 采样及等待约 **40.42 ms**。要衡量埋点开销，需用同一型号的 GPU、相同负载与配置做对照。

四种固定负载在 A10G 上全部完成，逐步 trace 核对通过。原始报告保存在 `out/`。

| 场景 | 吞吐（tok/s） | TTFT p99 | TBT p99 | 抢占次数 |
|---|---:|---:|---:|---:|
| `steady_decode` | 3,076 | 27.84 s | 79 ms | 129 |
| `mixed_long_short` | 4,089 | 0.47 s | 104 ms | 0 |
| `kv_pressure` | 2,878 | 131.17 s | 99 ms | 418 |
| `many_small` | 15,433 | 0.22 s | 30 ms | 0 |

A10G 上 18 项测试通过。prefill 关闭因果遮罩后，较早的 prompt 位置能看到后面的 token，后续层的 K、V 随之变化。平均匹配长度从基线的 **14.75** 掉到 **0**，平均 NLL 从 **0.513** 升到 **约 1.045**，检查退出码为 **1**。恢复后用同一份基线再比，结果为 `OK`。
